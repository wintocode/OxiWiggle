## Implementation review of 0.0.7-m3

The installed file matched the archived checkpoint byte for byte. All four Java suites passed in a fresh run and all 16 recompiled classes matched their installed counterparts.

**Display recovery finding.** A display send can throw after the transport has accepted the frame. If Bitwig returns to the previously displayed value before the delayed retry, the session treats the old cache entry as current and skips the corrective send. An offline probe using SessionFixture reproduced zero corrective frames for both a ring returning to 50% and a title reverting to its previous name. No hardware fault was reported.

Invalidate the attempted ring or labels cache entry before sending and restore it only on successful return in the same session. Add both return-to-previous-state cases to the regression suite and recheck the revised checkpoint before M4.

Two minor text cases also merit regression tests. “Cut Off” clips to “Cut ” while “Cut” clips to “Cut”. The native field pads both to identical bytes, yet the cache sends the labels again. Also, a valid page named only with combining marks can normalize to an empty title and show “OxiWiggle”. Apply the “Page N” fallback after normalizing a valid page name.
